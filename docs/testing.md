# 开发与验证

## 离线回归

使用 Python 3.12 或更高版本，在虚拟环境中安装依赖并运行：

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m compileall -q duifene main.py
git diff --check
```

测试使用合成身份、模拟 HTTP 响应和本地生成的二维码，不需要真实账号，不请求平台，不提交签到。
CI 在 Windows、Linux 的 Python 3.12、3.14 上运行同一套回归；GUI 本身需要桌面与 WebView2，不在离线测试中启动。

覆盖范围包括：HTTP/业务 403 与登录态保留、学生记录归属、活动有效期、数字码前导零、
材料按活动/教学班匹配、二维码格式、网页会话恢复，以及发现/取码分频和截止前优先取码。
当前合计 77 项；新增回归覆盖独立取码退避及重置、封顶日志去重、空发现保留/清理候选、人数缓存过期/身份隔离，以及截止窗口内人数更新。

临近截止时，人数首次返回 0、下一轮已达到门槛，1 秒缓存仍可能使程序继续等待。
截止前 5 秒因此每次重新查询人数，其他时段保留缓存；人数阈值与活动有效期检查不变。
两个新增回归分别覆盖总人数从 0 恢复，以及签到占比跨过门槛。
修复已在自有测试课通过两轮 30 秒数字签到，分别使用候选入口与正常 `main.py` 入口，由教师端确认出勤。
以上验证不能推断此前所有失败都由人数缓存造成；材料在到期后才到达时仍不会提交。

## 私有脚本与旧接口迁移

`tests/*` 默认忽略，仅白名单中的三个合成数据测试入库；新增公开测试应先检查数据来源再加入白名单。
验证忽略策略可使用：

```sh
git check-ignore --no-index tests/e2e_student_checkin.py
git check-ignore --no-index tests/test_permissions.py
```

第一条应输出私有路径并返回 0；第二条不应输出路径，返回 1 表示该合成测试没有被忽略。
`.gitignore` 只控制未跟踪文件，不会移除已提交文件或清理历史；它不能替代提交前检查。

私有 e2e 若调用旧的 `api.fetch_active_activity(course_id)`，需要先使用 `api.fetch_courses()` 取得
完整 `Course`（包含 `class_id`），然后改为 `api.fetch_active_activities(course)` 并逐条处理返回活动。
低层 `DfAppApi.fetch_active_checkin()` 仅为旧接口的 HTTP/业务 403 回归保留，不能用作学生监听入口。

## 人工受控验收

只在自己管理的测试课进行，并使用独立学生账号加入测试班：

1. 使用学生账号启动桌面程序，选择测试课，开始监听。
2. 老师端发起至少 60 秒的数字签到；不向程序手工输入教师端显示的码。
3. 确认程序发现活动并等待材料，在截止前自动取码提交。
4. 同时核对程序结果和老师端出勤记录；成功后观察是否重复提交。
5. 分别验证提前结束、缺码、权限拒绝与网络异常，不把缺码提示视为成功。

默认发现间隔为 3–5 秒，受界面设置控制；数字取码在前一次请求完成后等待 0.2 秒，最后 5 秒优先处理。
实际周期受网络耗时影响，代码不保证所有课程或网络下必签成功。
取码可重试失败等待 0.4、0.8、1.6、2 秒，成功后恢复 0.2 秒；只有首次失败与首次封顶记录日志。
空发现保留的候选仍按归属、有效期与旧活动上限清理，不能把缓存当作活动继续有效的保证。
人数缓存 TTL 为 1 秒，截止前 5 秒绕过缓存，按学生、教学班、活动隔离；停止后重新开始监听会清空缓存。

数字码和静态二维码的已有验收分别见 [数字码](student-numeric-validation.md)、[二维码](student-qr-validation.md)。
汉字、定位和动态二维码的成功提交不在本轮验收范围内。

发布前请重新安装依赖并重启源码进程；Windows EXE 必须按 README 重新构建。
不要把本机配置、Cookie、Token、密码、原始网络捕获或学生名单加入提交。
