# 学生数字码与双轮询验收（2026-11-10）

## 结果与来源

自有“测试”课完成四轮学生自动取码成功提交，其中两轮由桌面程序完成。
老师端仅创建自有测试活动及核对出勤，没有向学生程序提供码、Cookie 或教师凭据。
只有学生身份的课程也不需要配置教师账号；实际可用性仍取决于平台返回与权限，未对其他课程作泛化验证。

```text
学生 App 登录 → 已加入课程/教学班 → GetStudentInLogList 当前学生记录
→ GetCheckIn 校验归属、类型、有效期、作废状态
→ 同一学生账号独立正常登录网页
→ POST /_CheckIn/MBCount.ashx
   action=gettclasscheckinlistbypage, classid=当前班级, page=1, nums=10
→ rows 按当前候选活动 ID、TClassID 匹配
→ 校验四位 ASCII 数字字符串并保留前导零
→ 原处理器与人数条件 → App 数字码提交
```

学生 App 详情 `checkInCode` 仍为空；网页 `CheckInCode` 在截止前约 1–2 秒出现。
早期数秒一次的查询漏掉了短窗口，“只能在结束后读码”的旧结论已被成功提交修正。
部分采样中网页 HTTP Date 比本机快约 1–1.5 秒；内部计时机制未知，不能推断固定开放时间。

## 两个轮询

入口为 `duifene/watcher.py`、`DuifeneApi.refresh_numeric_materials()`、`duifene/web_api.py`。

| 阶段 | 调度与请求 |
| --- | --- |
| 活动发现 | 沿用界面配置，本次 3–5 秒；查询学生记录与候选 App 详情 |
| 已发现数字活动、缺码 | 每次网页取码请求完成后等 0.2 秒；不重复 App 记录/详情查询 |
| 截止前 5 秒 | 优先取码，暂缓慢的发现查询；有材料后立即交处理器 |
| 成功、到期、停止或离开监听窗口 | 清除快速取码任务，恢复正常发现或停止 |

同一学生会话没有并发取码；实际周期包含网络耗时，不保证每秒 5 次。
人数门槛、静默限流、身份、班级与有效期检查仍保留，截止时间取 App 与网页的较早值。
提前结束或作废可能先于下一次活动发现，服务端仍会最终判定；窄窗口不能保证必签成功。

## 真实活动

时间均为北京时间，仅操作自有测试课。活动与教学班标识不随文档公开。

| 活动 | 流程 | 观察与结果 |
| --- | --- | --- |
| A | 学生独立取码原型 | 08:11:20.539 读到码，有效至 08:11:21；前导零保留，提交成功，教师出勤 1 |
| B | 从约 81 秒剩余时间开始采样 | 剩余 2.123 秒仍无记录，1.335 秒时出现；成功时剩余约 0.810 秒 |
| C | 接入取码后的桌面程序 | 08:23:52 发现，08:24:46 成功；教师出勤 1、缺勤 0 |
| D | 独立双轮询桌面程序 | 08:37:47 发起，60 秒有效；08:37:49 发现，08:38:45 成功；教师出勤 1、缺勤 0 |

最后一轮没有外部脚本代为提交或注入教师码；桌面启动日志为空。
另一次教师已知码的控制测试只验证提交链，不计作上述学生自动取码成功。
原始截图、响应、凭据和会话文件不随仓库发布。上述为人工受控验收，不能替代其他账号的验证。

## 其他入口排查与限制

官方 APK v2.3.1 经 Blutter 对象池及 ARM64 调用点分析恢复部分请求格式，许多函数尚未完整恢复。

- 学生 `/CK/GetModelByInProgress/{course_id}` 被拒绝，已退出监听链路。
- 先前猜测三段路径的班级列表返回 404；实际调用为
  `POST /CK/GetTClassCheckInListByPage/{class_id}`，JSON `page=1, limit=20`，学生请求仍为 403。
- `/CK/GetCheckingByLog` 的 `CheckInIds` 请求返回日志，没有发现新的实时数字码来源。
- 学生普通网页登录后旧移动取码页仍返回 500；异常栈不能证明必须微信登录，未要求用户继续扫码。

60 项离线测试通过，覆盖权限、材料错配、缺码、过期、前导零、网页恢复、双轮询、最后 5 秒优先取码、快速路径不重查 App 及成功后退出。
静态二维码独立流程保留，见 [二维码验收](student-qr-validation.md)。
本次更新源码和依赖，未重建旧 Windows EXE。桌面验收后另补修了非空无效数字码也进入快速取码的边界，已通过离线回归。
其他课程、账号、网络以及汉字、定位、自动刷新二维码没有完成本轮同等验收。
